Three kinds of links

Within a page

Jump down to a spot. You did this in HTML-2.

href="#huberman"

Between your pages

Go to another file in your folder. This is what makes a site.

href="alex.html"

Out to the world

Another website, or an email.

href="https://gonzaga.edu" href="mailto:you@…"

Every link has two parts

<a href="
alex.html
">
Alex's page
</a>

href: where it goes

A file name in your folder, a full https:// address, or mailto:.

The text: what you click

Anything you want. "Alex's page", "Email me", "Gonzaga".

The file name must match exactly. Alex.html is not alex.html.

    Three places a rule can live

    External

    One styles.css file. Every page that links to it gets the same look.

    HTML-3. Change once, every page changes.

    Internal

    A <style> block at the top of one page.

    HTML-1 and HTML-2. Only that page.

    Inline

    A style="…" on one tag.

    Only that one tag.

    When they disagree, the closest one wins: inline beats internal beats external.

    Your first fix: find the plain page

    1. Click every menu link on your live site.
    2. One page looks plain. Which one?
    3. Open its code and another page's code. Compare the <head> line by line.
    4. One line is missing. Add it, commit, check.

    Comparing something broken to something that works is how most bugs get found.

    HTML-3's usual suspects

    1. A page looks plain? Its <link> line is missing or misspelled.
    2. A menu link shows a 404? The href doesn't match the file name exactly.
    3. A new style does nothing? Look for a missing ; or }.
    4. Email link opens a web page? It needs mailto: in front.
    5. Still stuck? "I expected ___, but I see ___." Search that.
